Персона «Анна», 25 лет, Санкт-Петербург, маркетолог, доход 90 000 ₽/мес, высшее образование. Шьёт на бытовом уровне, интересуется модой, индивидуальным стилем и соцсетями.

## 2. Три сессии уточнения (15 вопросов)

### 2.1 Сессия 1 — продукт и объём MVP

| № | Вопрос | Ответ |
|---|---|---|
| 1.1 | Модель монетизации | Продажа выкроек поштучно |
| 1.2 | Кто создаёт контент | Собственная команда конструкторов |
| 1.3 | Что обязательно в MVP | Каталог с фильтрами и карточкой; регистрация/вход и ЛК с историей покупок; корзина, оплата, скачивание PDF |
| 1.4 | Что такое «кастомизация» | Автоподбор размера по меркам и росту **+** параметрическая правка (длина, рукав, вырез, посадка) |
| 1.5 | Гео и платежи | РФ, русский язык, рубли, карта + СБП |

Следствия: 3D, сообщество и ателье из MVP исключены; кастомизация стала ядром продукта, а не «приятным дополнением»; валюта и язык фиксированы — мультиязычность не делаем.

### 2.2 Сессия 2 — файлы, размеры, админка

| № | Вопрос | Ответ |
|---|---|---|
| 2.1 | Форматы выкроек | PDF A4, PDF A0 и «в MVP только PDF A4, остальное позже» (противоречие — см. 2.4) |
| 2.2 | Механика параметрической правки | Генерация из параметрической мастер-модели |
| 2.3 | Доступ к купленным файлам | Бессрочно в ЛК, без лимита скачиваний |
| 2.4 | Роли и админка | Каталог/выкройки/файлы/категории; заказы, промокоды, пользователи; отчёты по продажам |
| 2.5 | Обязательные поля карточки | Расход ткани, материалы, припуски; уровень сложности и время пошива; фото готового изделия |

Следствия: покупатель должен видеть «что получит» ещё до оплаты (расход, сложность, фото) — это ядро конверсии карточки; админка — не «просмотр», а полноценный CRUD; личный кабинет становится библиотекой, а не списком заказов.

### 2.3 Сессия 3 — платформа, юридика, запуск

| № | Вопрос | Ответ |
|---|---|---|
| 3.1 | Платформа/стек | «Не знаю, учебный проект; желательно бесплатно или дёшево; только MVP, чтобы не тратиться» |
| 3.2 | Платежи и юридика | Эквайринг карта + СБП + чеки; оферта и лицензия; 152-ФЗ (политика ПД, согласия); защита файлов и водяные знаки |
| 3.3 | Визуализация и 3D | Интерактивный 3D-просмотр (вращение модели) |
| 3.4 | Когда сообщество и ателье | Всё в Release 2+ |
| 3.5 | Сроки, команда, бюджет | «Учебный проект, денег нет, из команды только я, срок пару недель» |

Следствия: проект переводится из режима «коммерческий запуск» в режим **учебного MVP с демонстрацией полного сценария**; реальный эквайринг, юрлицо, чеки и модерация UGC в объём не входят (заглушки и дисклеймеры); всё, что нельзя сделать за 2 недели силами одного человека, выносится в Release 2+ с явной пометкой.

### 2.4 ❗Решения по противоречиям

| Противоречие | Решение | Почему |
|---|---|---|
| 2.1: выбраны PDF A4 **и** A0 **и** «только A4 в MVP» | **MVP — только PDF A4.** A0 и DXF/PLT/SVG → Release 2 | Один формат = один пайплайн печати и контроля масштаба. A0 не даёт учебному MVP новой ценности |
| 2.2: «генерация из мастер-модели» vs 2 недели и 0 ₽ | **Упрощённая параметрика на пресетах:** лекала заранее отрисованы под ограниченный набор вариантов; система выбирает нужный файл по комбинации параметров и подставляет титульный лист с мерками. Полная CAD-генерация → Release 2+ | Параметрический CAD-движок — это месяцы и лицензии. Пресеты дают тот же пользовательский сценарий за 1–2 дня |
| 3.1: «бесплатно/дёшево» + кастомный веб | **Next.js + Supabase + Vercel, free tier.** Никаких платных сервисов, PDF не генерируются в рантайме | Всё перечисленное бесплатно на учебных объёмах; генерация PDF на лету не нужна при пресетах |
| 3.2: эквайринг + чеки 54-ФЗ + оферта | **Оплата — эмуляция («демо-платёж»)**; оферта, политика ПД и согласие — реальные страницы и чекбоксы; чеки и водяные знаки — Release 2 | Для учебного проекта нет ИП/ООО и договора эквайринга. Эмуляция сохраняет весь пользовательский путь |
| 3.3: интерактивный 3D-просмотр | **3D — 1–2 демо-модели** через `<model-viewer>` и готовый `.glb`; остальные выкройки — фото. Если модели нет — фото-галерея, 3D помечается как Release 2 | Создание 3D-моделей — отдельная компетенция и бюджет. Просмотр готового GLB — часы работы |
| 2.4: фильтры по карте в Release 2 | **Базовые фильтры и сортировки — в MVP** (тип одежды, размер, сложность, цена, сортировка по цене/новизне), стиль и теги → Release 2 | Боль №1 персоны — «сложно искать». Каталог без фильтров не демонстрирует ценность |
| 2.4: промокоды и отчёты | **В MVP в упрощённом виде:** одно поле промокода со скидкой и один экран «Сводка продаж» (сумма, количество заказов, топ-3 выкройки) | Стоимость — несколько часов, а на демонстрации закрывает эпик «Управление продажами» |

## 3. Рамки проекта

### 3.1 Цель и критерий успеха

**Цель:** за ~2 недели силами одного разработчика собрать работающий учебный MVP SewIt, который проводит пользователя по полному пути «нашёл → примерил размер → настроил → купил → скачал» и показывает админский контур управления каталогом.

**Критерий успеха:** демо-сценарий из раздела 13 проходит без ручных правок в БД на мобильном и десктопе, деплой доступен по публичной ссылке.

### 3.2 Ограничения

| Ограничение | Влияние на ТЗ |
|---|---|
| 1 разработчик, ~10 рабочих дней | Только «вертикальный срез»: ни одной функции без готового UI и данных |
| Бюджет 0 ₽ | Только free tier; никаких платных API, аналитики, CDN и 3D-конвертеров |
| Нет дизайнера | UI на готовой библиотеке компонентов (shadcn/ui + Tailwind), без кастомной иллюстрации |
| Нет конструктора в команде | Контент — открытые лекала с разрешённой лицензией либо собственные простые лекала; 4–6 моделей |
| Учебный статус | Нет юрлица, эквайринга, 54-ФЗ и модерации; вместо них — эмуляция и дисклеймеры |
| 1 человек = нет код-ревью | Обязательны типизация, линтер и ручной чек-лист перед деплоем |

### 3.3 In scope / Out of scope

**Входит в MVP:**

* каталог: сетка карточек, категории, базовые фильтры, сортировки, поиск по названию;
* карточка выкройки: фото, описание, таблица размеров, расход ткани, материалы, припуски, сложность, время пошива;
* подбор размера по меркам с рекомендацией и предупреждениями;
* кастомизация параметров (пресеты) с пересчётом состава набора;
* корзина (локально), оформление заказа, демо-оплата, промокод;
* регистрация/вход, ЛК: история покупок, библиотека, повторное скачивание;
* скачивание PDF A4 по защищённой ссылке с ограниченным TTL;
* админка: выкройки, категории, файлы, заказы, промокоды, сводка продаж;
* 3D-просмотр на 1–2 моделях (stretch);
* страницы инструкции по пошиву (текст) и правовые заглушки;
* адаптив, SEO-метатеги, OG-картинки, sitemap.

**Не входит (Release 2+):**

* реальный эквайринг, чеки 54-ФЗ, возвраты;
* подписка, подарочные сертификаты, баланс;
* отзывы, фото покупателей, публикации, комментарии, ИИ-помощник;
* ателье: каталог партнёров, поиск, передача заказа и мерок;
* форматы A0/DXF/PLT/SVG, водяные знаки и DRM;
* полноценная CAD-параметризация, 3D-примерка на аватаре и редактирование 3D-тканей;
* рекомендации, планирование публикаций, мультиязычность и мультивалютность;
* мобильное приложение, офлайн-режим.

## 4. Функциональные требования MVP

Приоритеты: **P0** — без этого демо не проходит, **P1** — нужно показать ценность, **P2** — stretch при оставшемся времени.

### FR-1. Каталог и поиск — P0

| ID | Требование | Критерий приёмки |
|---|---|---|
| FR-1.1 | Сетка карточек выкроек с обложкой, названием, ценой, сложностью | На `/catalog` видно ≥6 карточек; карточка кликабельна целиком |
| FR-1.2 | Категории (платья, юбки, брюки, топы, верхняя одежда) | Выбор категории фильтрует выдачу; счётчик найденного обновляется |
| FR-1.3 | Фильтры: тип одежды, размер, сложность, диапазон цены | Комбинация фильтров сохраняется в URL (`?category=&size=&level=&price=`) и переживает перезагрузку |
| FR-1.4 | Сортировка: по цене ↑/↓, по новизне, по популярности (по числу покупок) | Смена сортировки меняет порядок без перезагрузки данных |
| FR-1.5 | Поиск по названию и описанию | Подстрока ≥2 символов; при пустом результате — понятное сообщение и сброс фильтров |
| FR-1.6 | Пустые состояния и скелетоны загрузки | Нет «прыжков» контента; при 0 результатах есть CTA «Сбросить фильтры» |

### FR-2. Карточка выкройки — P0

| ID | Требование | Критерий приёмки |
|---|---|---|
| FR-2.1 | Галерея фото (3–5 шт.) + 3D-просмотр, если есть `.glb` | Переключение фото работает; при наличии модели открывается 3D-вьюер |
| FR-2.2 | Описание, состав набора, уровень сложности, время пошива | Все поля обязательны к заполнению в админке (валидация) |
| FR-2.3 | Расход ткани (по размерам), материалы, припуски | Расход отображается таблицей/списком и меняется при выборе размера |
| FR-2.4 | Таблица размеров (размер, ОГ, ОТ, ОБ, рост) | Таблица доступна без покупки и без регистрации |
| FR-2.5 | Выбор размера и параметров (см. FR-3, FR-4) | Итоговая цена и состав набора обновляются сразу |
| FR-2.6 | CTA «В корзину» / «Купить сейчас», избранное | Кнопка недоступна для черновика; гость при покупке уходит на вход и возвращается в карточку |

### FR-3. Подбор размера по меркам — P1

| ID | Требование | Критерий приёмки |
|---|---|---|
| FR-3.1 | Форма ввода мерок: ОГ, ОТ, ОБ, рост (см), валидация диапазонов | Некорректные значения блокируют расчёт с подсказкой |
| FR-3.2 | Рекомендация размера с обоснованием (алгоритм — раздел 6.1) | Выводится размер, ближайшие альтернативы и текстовое пояснение |
| FR-3.3 | Предупреждения: пограничный размер, несоответствие роста, расхождение мерок | Предупреждение не блокирует покупку, но фиксируется в заказе |
| FR-3.4 | Сохранение мерок в профиле | Мерки доступны при следующем заходе; можно удалить (152-ФЗ) |

### FR-4. Кастомизация выкройки — P1

| ID | Требование | Критерий приёмки |
|---|---|---|
| FR-4.1 | Параметры: длина (mini/midi/maxi), рукав (нет/короткий/длинный), вырез (круглый/V/лодочка), посадка (по фигуре/оверсайз) — набор настраивается для каждой выкройки | Для выкройки без параметров блок не показывается |
| FR-4.2 | Выбор комбинации → система определяет файл-вариант | Пользователь видит название варианта и превью; недоступная комбинация помечена «в разработке» |
| FR-4.3 | Фолбэк: если файла под комбинацию нет — базовый вариант + явная пометка | Покупка не блокируется, пометка сохраняется в заказе |
| FR-4.4 | Титульный лист PDF с выбранными мерками и параметрами | В скачанном PDF первая страница содержит мерки, размер, параметры и дату покупки |

### FR-5. Корзина, заказ, оплата — P0

| ID | Требование | Критерий приёмки |

## 6. Алгоритмы

### 6.1 Подбор размера по меркам

```
d_i = 0.4·|ОГ − b_i|/b_i + 0.3·|ОТ − w_i|/w_i + 0.3·|ОБ − h_i|/h_i
```

1. Считаем `d_i` для каждого размера выкройки, выбираем минимум → рекомендуемый размер.
2. Если `d_2 − d_1 < 0.03` → «пограничный размер»: советуем отталкиваться от доминирующей мерки (грудь — для плечевых изделий, бёдра — для поясных) и показываем оба варианта.
3. Если `|рост − средний рост размера| > 4 см` → предупреждение о необходимости корректировки длины по лекалам.
4. Если расхождение ОГ/ОТ/ОБ > 2 размеров → предупреждение «потребуется подгонка по талии/бёдрам».
5. Результат и предупреждения сохраняются в `orders.measurements_snapshot` для истории.

### 6.2 Кастомизация через пресеты

* У выкройки есть `pattern_params`; каждое значение параметра имеет флаг `available`.
* Итоговый `variant_key` — нормализованная строка выбранных параметров (порядок фиксирован, `none` для выключенных).
* Поиск файла: точное совпадение `(size_id, variant_key)` → если нет, ищем `variant_key` с `none` по необязательным параметрам → если нет, базовый файл + пометка «вариант в разработке».
* Цена варианта на MVP одинаковая; наценка за расширенные параметры — Release 2.
* Титульный лист PDF генерируется при скачивании (одна страница, `pdf-lib`) с мерками, размером, параметрами и датой — это единственная серверная генерация.

### 6.3 Выдача файла

`entitlement` → серверная проверка права → подписанный URL (TTL 10 мин) → редирект на скачивание → запись в `download_log`.
Без авторизации и без entitlement скачивание невозможно; публичный доступ к бакету с лекалами закрыт.

### 8.2 Версии и правило фиксации

❗В проекте нет «примерно таких» версий: единственный источник истины — `pnpm-lock.yaml`, закоммиченный в репозиторий. CI и Vercel ставят зависимости строго по нему (`pnpm install --frozen-lockfile`), `package.json` хранит только диапазоны.

| Компонент | Минимальная major-линия | Чем фиксируется |
|---|---|---|
| Node.js | 22 LTS | `.nvmrc`, `engines.node` |
| pnpm | 10 | поле `packageManager` |
| Next.js / React | 15 / 19 | `pnpm-lock.yaml` |
| TypeScript | 5 | `pnpm-lock.yaml`, `tsconfig.json` |
| Tailwind CSS | 4 | `pnpm-lock.yaml` |
| Supabase JS / SSR | 2 / 0.x (pre-1.0 — только точная версия) | `pnpm-lock.yaml` |
| Supabase CLI | 2 | `devDependencies`, точная версия |
| `zod` / `zustand` / `pdf-lib` | 3 / 5 / 1 | `pnpm-lock.yaml` |
| Vitest / ESLint / Prettier | 3 / 9 / 3 | `pnpm-lock.yaml` |
| `@google/model-viewer` | актуальный стабильный релиз | `pnpm-lock.yaml` |

Правила:

1. **День инициализации = день 1.** Версии берутся как «актуальный стабильный релиз»: `pnpm add next react …` без номера, затем lockfile коммитится вместе с каркасом.
2. Запрещены `canary`, `beta`, `rc`, тег `next` и `latest` в CI. Только стабильные релизы.
3. «Минимальная major-линия» — нижняя граница совместимости, а не целевая версия. Patch и minor в ТЗ не фиксируются: их определяет установка дня 1.
4. Версии не двигаются до сдачи MVP. Исключение — security-патч: отдельный коммит `chore(deps)`, прогон CI, запись в журнал `doc/README.md`.
5. `engines.node` и `.nvmrc` совпадают (иной major Node — ошибка окружения); проверки версий: `pnpm outdated` — день 1, `pnpm audit --prod` — день 10 перед деплоем.

### 8.4 Локальный запуск

Требования: Node.js 22 LTS, pnpm 10 (через `corepack`), Docker Desktop (для локального Supabase), Supabase CLI 2.

```powershell
corepack enable
pnpm install --frozen-lockfile
supabase start        # Postgres, Auth, Storage, Studio в Docker
supabase db reset     # миграции из supabase/migrations + seed.sql
pnpm dev              # http://localhost:3000
pnpm lint; pnpm typecheck; pnpm test
```

Windows: PowerShell 7, Docker — с WSL2-бэкендом. Если Docker недоступен, вместо локального стека используется отдельный dev-проект Supabase (`supabase link`), миграции — `supabase db push`.

| Переменная | Доступ | Назначение |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | браузер и сервер | URL проекта Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | браузер и сервер | Публичный ключ, доступ ограничен RLS |
| `SUPABASE_SERVICE_ROLE_KEY` | ❗только сервер | Обход RLS: подпись URL, заказ, админ-операции. В браузер не попадает никогда |
| `SUPABASE_PROJECT_REF`, `SUPABASE_ACCESS_TOKEN` | локально и CI | `supabase link` / `db push`; в Vercel не задаются |
| `NEXT_PUBLIC_SITE_URL` | браузер и сервер | Канонический URL для OG, sitemap, redirect после входа |
| `DOWNLOAD_URL_TTL_SECONDS` | сервер | TTL подписанной ссылки, по умолчанию `600` (FR-7.1) |
| `NEXT_PUBLIC_DEMO_PAYMENT` | браузер | Флаг демо-оплаты и дисклеймеров FR-9.4 |

Состав `.env.example`: эти ключи с пустыми значениями и комментарием в одну строку, без реальных секретов. `.env*.local` — в `.gitignore`; секреты продакшена — только в настройках Vercel и Supabase.

| Модуль | Что проверяем | Почему автоматизируем |
|---|---|---|
| `lib/size-fit.ts` | Формулу 6.1 на фикстурах, границу `d₂ − d₁ < 0,03`, рост > 4 см, расхождение > 2 размеров, выбор при равенстве | Ядро продукта: ошибка = неверная рекомендация в демо |
| `lib/variant.ts` | Нормализацию `variant_key` (порядок параметров, `none`), разбор строки, цепочку фолбэка: точно → `none` → базовый файл | Ошибка = «файл не найден» после оплаты |
| `lib/promo.ts` | Валидный, просроченный, исчерпанный, выключенный промокод; скидка и итог в копейках | Деньги и лимиты — частая причина регрессий |
| `lib/pricing.ts` | Итог корзины, округление, скидка не больше суммы | Числа должны совпадать в чеке, ЛК и сводке |
| `lib/entitlements.ts` | Чистую функцию «есть ли право»: свой и чужой entitlement, отозванный заказ | Доступ к чужим файлам — критическая утечка |

Не автоматизируем в MVP: E2E-сценарии (ручной смоук раздела 13 на 360 и 1440 px), RLS (`scripts/check-rls.sql` + ручной сценарий), вёрстку PDF и титульного листа, 3D-вьюер, a11y (Lighthouse + проход вручную), письма восстановления пароля, кросс-браузерность. Причина одна: 10 дней и один разработчик — эти проверки дешевле делать руками перед деплоем, чем поддерживать Playwright. Запуск: `pnpm test` (Vitest, без сети и БД), `pnpm test:watch`; тесты — обязательная часть CI (8.1).

### 8.7 Безопасность и приватность

| Механизм | Реализация | Критерий |
|---|---|---|
| RLS | Включён на всех таблицах раздела 5; политики по таблицам — в `doc/architecture.md`; helper `is_admin()` по `profiles.role` | Аноним читает только `published`; пользователь — только свои `orders`, `measurements`, `entitlements`, `favorites` |
| Файлы | Бакет лекал приватный, обложки — публичный бакет; PDF только по подписанной ссылке с TTL 10 мин | Прямой URL без подписи → 400/403 (FR-7.1) |
| `service_role` | ❗Только серверные модули (`lib/supabase/server.ts`, `import 'server-only'`), никогда в `NEXT_PUBLIC_*` | Ключа нет в клиентском бандле (проверка `grep` в CI) |
| Проверка прав | `lib/entitlements.ts` вызывается в route handler до подписи URL; `orders` правами не управляет | Чужой `entitlementId` → 403 (FR-7.2) |
| Rate limit | Лимиты Supabase Auth на вход; скачивания — счётчик по `download_log` (N в минуту на пользователя); промокод — атомарный `UPDATE … WHERE used_count < max_uses` | Повторные клики и перебор промокодов не проходят |
| Валидация | Все входы через `zod`-схемы; мутации — серверные экшены с проверкой сессии | Нет записи в БД без серверной валидации |
| Секреты | `.env*.local` в `.gitignore`; прод — только в Vercel/Supabase; `SUPABASE_ACCESS_TOKEN` не в Vercel | Секретов нет в git и в клиентском бандле |
| Приватность | Только e-mail и мерки; согласие при регистрации; удаление аккаунта обезличивает заказы; сторонней аналитики нет | 152-ФЗ: минимум ПД, нет передачи третьим лицам |
| Заголовки | `X-Content-Type-Options`, `Referrer-Policy`, запрет `frame-ancestors` в `next.config.ts` | Базовая защита без платного WAF |

### 8.8 ADR: решение — альтернативы — почему отклонены

| Решение | Альтернативы | Почему отклонены |
|---|---|---|
| Next.js App Router + RSC | Vite SPA + Express; Django-шаблоны | SPA проигрывает по SEO и LCP и требует второй кодбейс; Django — второй язык и свой слой авторизации |
| Supabase (Postgres/Auth/Storage/RLS) | Firebase; Django + Postgres на VPS; SQLite | Firebase — NoSQL и vendor lock; VPS — администрирование и деньги; SQLite не даёт Auth, Storage и RLS |
| Пресеты вместо CAD-генерации лекал | Seamly2D/OpenSCAD-автогенерация; клиентский CAD | Месяцы работы и лицензии; не влезает в 10 дней и 0 ₽ (см. 2.4) |
| Только PDF A4 + `pdf-lib` | A0/DXF/SVG; Puppeteer; серверный LaTeX | Второй пайплайн печати и контроля масштаба; headless-браузер не влезает в лимит функции и холодный старт |
| `entitlements` + signed URL | Публичный бакет; стриминг файла через функцию | Публичный бакет = утечка платного контента; стриминг съедает egress и время функции |
| Корзина в `localStorage` + `zustand` | Серверная корзина; cookie | Серверная корзина требует гостевых сессий и миграции при входе; cookie ограничены 4 КБ |
| Vitest, без E2E | Playwright/Cypress; Storybook | E2E за 10 дней дороже ручного смоука; Storybook не нужен без дизайнера |
| `model-viewer` + GLB | three.js-сцена; Sketchfab embed | Своя сцена = недели; внешний хостинг = платный аккаунт и лишние ПД |
| Vercel Hobby | VPS; Netlify; GitHub Pages | VPS — администрирование и 0 ₽ только на месяц; Netlify хуже поддерживает App Router; статика не даёт SSR/ISR |
| shadcn/ui копированием | MUI/Ant Design; своя библиотека | UI-кит тянет свой рантайм и стили; своя библиотека — недели работы |
| Zod + react-hook-form | Yup; самописная валидация | Zod даёт одну схему и типы на клиент и сервер; самопис дублирует правила |
| GitHub Actions | Только проверки Vercel; pre-commit-хуки | Vercel не запускает тесты; хуки обходятся и не видны в PR |
| Без Sentry и сторонней аналитики | Sentry free; Яндекс.Метрика/GA | ПД и согласия, лишний код; для демо хватает логов Vercel и запросов к БД |
| Миграции через Supabase CLI | Правки в Studio; ручной SQL | Studio не версионируется, ручной SQL не воспроизводим на новом окружении |

### 8.9 Риски стека и митигация

| Риск | Вероятность | Влияние | Митигация |
|---|---|---|---|
| Free tier Supabase уходит на паузу или упирается в egress | Средняя | Критическое для демо | Прогрев за час, локальный дамп, PDF ≤ 0,5 МБ, WebP, ISR-кэш, ленивая загрузка 3D |
| `@supabase/ssr` (pre-1.0) меняет API cookie | Средняя | Среднее | Точная версия в lockfile, cookie-код изолирован в `lib/supabase/*` |
| Ошибка в RLS открывает чужие заказы или файлы | Средняя | Критическое | `scripts/check-rls.sql` перед деплоем, ручной сценарий «чужой entitlement → 403», тесты чистой функции прав |
| Лимит длительности функции Vercel Hobby | Низкая | Среднее | Только подпись URL и одна страница `pdf-lib`, без тяжёлой генерации |
| Холодный старт и раздутый клиентский бандл | Средняя | Среднее | RSC по умолчанию, `zustand` только в корзине, `next/image`, бюджет < 250 КБ из раздела 7 |
| Docker на Windows не поднимается → нет локального Supabase | Средняя | Среднее | Фолбэк: отдельный dev-проект Supabase + `supabase link` |
| Встроенный SMTP Supabase ограничен по числу писем | Средняя | Низкое | Письма нужны только для сброса пароля; демо на них не опирается, в UI — подсказка «обратитесь к администратору» |
| Нет ревью, регрессия в алгоритмах | Средняя | Высокое | Vitest в CI, `typecheck` и `lint` как гейт, фриз фич за день до защиты |

## 12. Метрики и приёмка

**Приёмка MVP (Definition of Done):**

1. `pnpm build` без ошибок и предупреждений TypeScript; ESLint чистый.
2. Демо-сценарий раздела 13 проходит на 360 px и 1440 px.
3. Каталог: ≥6 выкроек, ≥3 размера у каждой, фильтры и поиск дают корректный результат.
4. Подбор размера даёт рекомендацию и хотя бы одно предупреждение на «пограничных» мерках.
5. Купленный PDF скачивается из ЛК; прямая ссылка на файл без подписи недоступна.
6. Админ может создать выкройку с нуля и она появляется в каталоге без правок в БД.
7. Ни одна страница не показывает сырые ошибки и «пустой экран» без объяснения.

**Продуктовые метрики (для будущего коммерческого запуска, не для сдачи):**

* конверсия «карточка → корзина» ≥ 8 %;
* конверсия «корзина → оплата» ≥ 40 %;
* доля заказов с использованным подбором размера ≥ 50 %;
* повторные покупки в течение 90 дней ≥ 20 %;
* доля возвратов/жалоб «не подошёл размер» ≤ 5 %.

## 13. Демо-сценарий защиты (7 шагов, ~5 минут)

1. Открыть каталог, показать фильтр «платья + размер 46 + средняя сложность» и сортировку по цене.
2. Открыть карточку платья-рубашки: фото, расход ткани, припуски, сложность, 3D-вращение.
3. Ввести мерки (ОГ 88, ОТ 70, ОБ 96, рост 168) → получить размер и предупреждение о посадке.
4. Выбрать длину midi и короткий рукав → увидеть состав набора и итоговую цену.
5. Добавить в корзину, применить промокод, оформить заказ через демо-оплату (показать дисклеймер).
6. В ЛК открыть библиотеку, скачать PDF, показать титульный лист с мерками и инструкцию по печати.
7. Зайти в админку: создать черновик выкройки, опубликовать, увидеть её в каталоге; открыть сводку продаж.

### Глоссарий

* **Выкройка (pattern)** — карточка модели в каталоге с лекалами, описанием и размерами.
* **Лекала** — сами файлы с контурами деталей для печати и раскроя.
* **Вариант (preset)** — комбинация параметров выкройки, для которой существует готовый файл лекал.
* **Entitlement** — право конкретного пользователя на скачивание конкретного файла.
* **Демо-оплата** — эмуляция платёжного сценария без реального списания средств.
* **MVP** — минимальный набор функций, демонстрирующий полный пользовательский путь.
