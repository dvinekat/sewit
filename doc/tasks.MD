## 1. Назначение

Бэклог переводит требования README (раздел 4), план (раздел 10) и стек (раздел 8) в задачи, которые можно брать в работу и закрывать по одному критерию готовности. Источник истины по прогрессу — чек-лист раздела 6 этого файла; реестр задач (раздел 5) меняется только вместе с оценкой, зависимостями и сметой (раздел 10).

Правило проекта: **ни одна задача не считается сделанной без критерия готовности из реестра**, даже если код «вроде работает». Один разработчик без ревью — единственная защита от регрессий, и это явный DoD плюс CI из README 8.1.

## 2. Легенда

### 2.1 Приоритеты

| Приоритет | Значение | Правило |
|---|---|---|
| **P0** | Без этого демо-сценарий (README 13) не проходит | Не вырезается никогда; при отставании режется что угодно другое |
| **P1** | Нужно, чтобы показать ценность продукта | Режется в последнюю очередь после P2, но до P0 |
| **P2** | Stretch: делается только при оставшемся времени | Первый кандидат на вынос в Release 2 (README 2.4) |

### 2.2 Оценки

* Оценка — в **часах одного разработчика**, включая написание тестов, самопроверку в браузере и правку по результатам.
* Плановая ёмкость — **8 ч в день × 10 дней = 80 ч**; отдельных «свободных» часов нет — буфер образуют вырезаемые задачи дней 9–10 (порядок сокращения — раздел 9).
* Оценка не включает: подготовку контента (отдельный поток E-11), ревью (его нет), ожидание деплоя.
* Округление — 0,5 ч; задача дешевле 0,5 ч должна быть частью другой задачи.

### 2.3 Обозначения

| Обозначение | Значение |
|---|---|
| ❗ | Критичное решение или узкое место; отступление фиксируется письменно |
| FR-x.y | Требование из README, раздел 4 |
| NFR (разд. 7) | Нефункциональное требование README, раздел 7 |
| День 1–10 | День плана README, раздел 10 |
| `[ ]` / `[~]` / `[x]` | Не начато / в работе / готово (ведётся только в разделе 6) |
